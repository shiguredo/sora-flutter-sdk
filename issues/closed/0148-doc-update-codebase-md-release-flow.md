# `CODEBASE.md` の「正式リリース」の定義を明記する

- Created: 2026-08-31
- Completed: 2026-09-11
- Polished: 2026-09-07
- Milestone: 2026.1.0

## 目的

`CODEBASE.md` の「正式リリース前」節にある「正式リリース」の定義が無く、canary 版 (`2026.1.0-canary.0`) が正式リリースに当たるのか判断できない状態を解消する。

## 現状

`CODEBASE.md` 22-26 行目の「正式リリース前」節は以下 1 項目のみである:

- 正式リリース前は変更履歴を `CHANGELOG.md` に残さないこと

現状は `pubspec.yaml` が `version: 2026.1.0-canary.0`、git タグが `2026.1.0-canary.0` のみで安定版タグが無く、「正式リリース前」に該当する。canary を正式とみなすか安定版のみを正式とするかの定義が無いため、将来の安定版公開時に条項の適用可否が曖昧になる。

PR 要否の区分は `shiguredo-git` スキルが変更対象ごとに定めており、本 issue では扱わない。`CHANGELOG.md` 追記の種別・タイミングは `0096` / `0097` が所有するため扱わない。

## 設計方針

- 「正式リリース前」節に「正式リリース」の定義を追記する: 安定版タグ (canary 接尾辞なし) の公開を指し、canary 版は正式リリース前に含める。
- 本 issue の実装時はブランチを切らず `develop` に直接コミットする (`shiguredo-git` の `AGENTS.md` / `CODEBASE.md` 特別ルールに従い、コミットメッセージは「整備」とする)。`Branch:` フィールドは適用外のため持たない。

## 完了条件

- [ ] 「正式リリース」の定義が `CODEBASE.md` の該当節に明記されている。

## 解決方法

対応不要として closed にする。

`release/2026.1.0` の整備で、`CODEBASE.md` の「正式リリース前」節そのものを削除した。定義を追記する前提 (「正式リリース前」節が存在し、その中に定義が無い) が無くなったため、`CODEBASE.md` への「正式リリース」の定義追記は行わない。
